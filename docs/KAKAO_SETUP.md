# 카카오톡 발송 세팅 가이드 (직접 수행용)

> 코드 구현은 완료되어 있습니다. 아래는 사람이 직접 해야 하는 외부 설정 순서입니다.
> Phase 0(공유하기)만 먼저 해도 되고, Phase 2(자동 발송)는 대행사 계약 후에 진행합니다.

---

## Phase 0 — 학생 주도 공유하기 (비용 0, 소요 ~30분)

앱 코드: `components/habit/kakaoShare.ts` (p5 "오늘 실천 내용 공유하기" 버튼에 연결됨).
키가 없어도 버튼은 복사 폴백으로 동작하므로, 아래 등록 전에도 깨지지 않습니다.

### 1. 카카오 개발자센터 앱 등록
1. https://developers.kakao.com 접속 → 로그인 → **내 애플리케이션 → 애플리케이션 추가하기**
2. 앱 이름: `NBASS` / 사업자명: 본인(개인도 가능)
3. **앱 키** 메뉴에서 **JavaScript 키** 복사

### 2. 사이트 도메인 등록
1. 내 애플리케이션 → **플랫폼 → Web 플랫폼 등록**
2. 사이트 도메인에 서비스 주소를 입력 (예: `https://nbass.io`, 개발 중이면 `http://localhost:3000`)
   - 뒤에 경로 없이 도메인만 입력합니다
   - 카카오 공유하기는 등록된 도메인에서만 동작합니다

### 3. 카카오톡 공유하기 활성화
1. 내 애플리케이션 → **카카오 로그인** 메뉴 (공유하기 사용 시 필요에 따라)
2. 별도 검수 없이 즉시 사용 가능 (친구·공유 API는 기본 제공)

### 4. 앱에 키 등록
1. 프로젝트 루트의 `.env` 파일에 추가 (`.env.example` 참조):
   ```
   VITE_KAKAO_JS_KEY="여기에_JavaScript_키_붙여넣기"
   ```
2. 개발 서버 재시작 (`VITE_` 변수는 시작 시점에 읽힙니다)

### 5. 동작 확인
1. Habit Clinic → p10 탭이 아닌 **p5(학부모 안심) 탭** → "오늘 실천 내용 공유하기" 클릭
2. **카카오톡 공유 화면이 열리면 성공**
3. 공유 화면이 안 뜨고 "복사되었습니다" 토스트가 뜨면: 키 오기입 또는 도메인 미등록 → 1~2단계 재확인
   - 브라우저 개발자도구 콘솔에 `Kakao` 관련 오류가 표시됩니다

## Phase 2 — 부모 자동 발송 (알림톡, 대행사 계약 후)

앱 코드: `server.ts` → `POST /api/kakao/parent-send` (알림톡 전용, 대체발송 없음, 미구성 시 501 반환).
템플릿 22종 정의: `services/parentTemplates.ts` (ID·빈도·변수 목록).

### 1. 카카오 비즈니스 채널 개설 (무료, 소요 ~1일)
1. https://center-pf.kakao.com → 새 채널 만들기 (채널명: `NBASS 학습 안심알림` 등)
2. **비즈니스 인증** 신청 (사업자등록증 필요 — 개인은 사업자 등록 후 가능)
3. 채널 공개 → 채널 ID(예: `@nbass_alim`) 메모

### 2. 알림톡 대행사 계약 (소요 ~1~3일)
- 업체 예시: 알리고, 솔라피, 비즈엠 (코드는 알리고 API 기준으로 작성됨)
- 계약 시 받는 값 4종을 `.env`에 등록 (서버 전용, 절대 브라우저에 노출 금지):
  ```
  KAKAO_ALIGO_APIKEY="..."
  KAKAO_ALIGO_USERID="..."
  KAKAO_SENDER_KEY="발신프로필키"
  KAKAO_SENDER_PHONE="발신대표번호"
  ```
- 선불 충전 (1~3만원) — 실제 발송분만 차감됩니다

### 3. 발신프로필·발신번호 등록
1. 대행사 콘솔에서 카카오 채널과 동일한 명의의 **발신프로필** 등록 → `senderKey` 발급
2. 발신용 대표번호 등록 → `KAKAO_SENDER_PHONE`
3. 위 2단계 값을 `.env`에 입력 후 서버 재시작

### 4. 템플릿 22종 승인 신청 (소요 수일, 반려 시 수정 재신청)
1. 대행사 콘솔 → 알림톡 템플릿 등록
2. 템플릿별 문안은 **코드의 `compileTemplate` 분기와 변수 구성이 일치**해야 합니다
   - 승인용 변수 자리: `services/parentTemplates.ts`의 각 템플릿 `variables` 목록 참조
     (예: `PARENT_NEW_REPORT` → 학생명·진단유형·처방요약·링크)
   - 상세 내용은 링크로 전달하고 본문은 고정 (재승인 최소화 설계)
3. 범용 2종(`PARENT_FREE_NOTICE`, `PARENT_FREE_PRAISE`)은 고정 골격(인사·서명·링크)을 그대로 제출 — 비어 있는 틀은 "변수 비중 과다"로 반려됩니다
4. 승인 후 발급되는 **템플릿 코드**를 `.env`에 템플릿별 등록:
   ```
   KAKAO_TPL_PARENT_NEW_REPORT="..."
   KAKAO_TPL_PARENT_WEEKLY_DIGEST="..."
   ... (사용하는 템플릿만 등록하면 됩니다. 22종 전부 한 번에 할 필요 없음)
   ```
   - 환경변수명 규칙: `KAKAO_TPL_` + 템플릿 ID (서버가 자동 매핑하므로 추가 코드 수정 불필요)
   - **권장 순서**: `WELCOME` → `WEEKLY_DIGEST` → `HABIT_MILESTONE` → `NEW_REPORT` 순으로 승인받고, 나머지는 운영하며 추가

### 5. 학부모 전화번호·수신동의 확보
1. 가입(또는 학부모 연동) 플로우에 **전화번호 + 항목별 수신동의 체크** 추가 필요 (현재 미구현 — Phase 2 개발 항목)
   - 기본값 권장: 주간·마일스톤 ON / 성적·수면 OFF
2. 정보통신망법상 수신동의 기록 보관, 거부 시 즉시 중단
3. 채널 추가 유도: 알림톡은 채널을 추가한 학부모에게만 도달합니다 (미추가분은 실패로 기록, 대체발송 없음)

### 6. 발송 로그 DB 이관 (개발 항목, 대행사 계약과 무관하게 가능)
- 현재 로그는 기기별 localStorage라 PC↔모바일 중복 방어가 안 됩니다
- Supabase 테이블 권장 스키마:
  ```sql
  create table kakao_send_logs (
    student_id text not null,
    template text not null,
    event_key text not null,
    sent_at timestamptz not null default now(),
    unique (student_id, template, event_key)
  );
  ```
- `services/parentSendPolicy.ts`의 `readLog`/`recordParentSend`만 이 테이블로 교체하면 됩니다 (키 규칙은 그대로)

### 7. 실발송 테스트 순서 (반드시 이 순서로)
1. 서버 로그에 `KAKAO_SENDER_NOT_CONFIGURED` 없이 뜨는지 확인 (501이 뜨면 2~4단계 미완료)
2. 오너 콘솔(OwnerDashboard) → 카카오 설정에서 **내 번호로 테스트 1통** 발송
3. 알림톡 수신 확인 → 대행사 콘솔에서 성공/차감 확인
4. `PARENT_WELCOME` 1종만 실제 운영 → 주간 브리핑으로 확대
5. 중복 테스트: 같은 리포트 발송 2회 시도 → 2회째 스킵되는지 로그 확인

## 비용 요약 (학부모 수 × 월 통수 × 10원)

| 구성 | 월 통수/명 | 50명 | 100명 | 300명 |
|------|-----------|------|-------|-------|
| 매일 1~2통 | 45통 | 22,500원 | 45,000원 | 135,000원 |
| 권장 (주간+마일스톤) | 8통 | 4,000원 | 8,000원 | 24,000원 |

- 실패분은 과금 없음, 대신 미도달 (대체발송 정책상)
- 초기 1회: 최소 충전 1~3만원 (쓸 돈), 템플릿 승인 무료

## 주의사항
- `.env`의 `KAKAO_*` 값은 절대 Git에 올리지 않습니다 (`.gitignore`에 `.env` 포함 여부 확인)
- 브라우저 코드(`services/kakaoNotificationService.ts`의 직접 호출)는 실발송에 사용하지 않습니다 — 반드시 서버 엔드포인트 경유
- 범용 템플릿 변수에는 서열·순위 표현 금지 (서버에서 400으로 차단됨), 광고성 문구 금지 (템플릿 정지 사유)
