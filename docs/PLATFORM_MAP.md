# 플랫폼 정리 지도 (개인용 단일 진실 공급원)

## 1. 정식 소유권

| 폴더 | 역할 | 상태 | 타입 정식본 |
|------|------|------|--------------|
| 루트 (`App.tsx`, `types.ts`, `services/`) | 전문가 PC앱, 정밀 진단과 처방의 단일 진실 공급원 | 정식 유지 | `types.ts` 699줄이 정식 |
| `android_app/` | 모바일 뷰어, 조회와 기록 위주 | 뷰어로 유지, 쓰기는 통합 동기화 경유 | `android_app/src/types.ts`는 모바일 표시용, 변환은 브리지 경유 |
| `src/` | 경량 성적과 오답 앱 | 보조 유지 | `src/types.ts`는 경량 도메인, 루트와 직접 혼용 금지 |
| `study/`, `schedule/`, `HTML/` | 실험용 미니앱 | 동결, 신규 수정 금지, 삭제 금지 (참조용 보관) | 각 `src/types.ts`는 실험용, 정식 반영 시 수동 이관 |
| `components/schedule-management/types.ts` | 스케줄 도메인 정식본 | 정식 유지 | 3533바이트가 정식 |
| `schedule/src/types.ts` | 위 파일의 복제본 | 복제본, 수정 시 정식본을 먼저 수정 후 복사 | 정식본과 동일 유지 |

## 2. 규칙

1. 신규 로직은 루트에만 작성합니다. 모바일과 경량앱은 읽기 전용으로 씁니다.
2. 타입을 직접 중복 정의하지 않고 `types/bridge.ts`의 변환 함수를 경유합니다.
3. 저장 키는 `nbass_` 접두사로 통일합니다. 안드로이드 키와 루트 키가 다르면 통합 동기화가 깨집니다.
4. 동기화는 `services/unifiedSyncService.ts` 하나만 호출합니다. 개별 `database.ts`와 `dataSyncService.ts`를 화면에서 직접 호출하지 않습니다.
5. 실험 폴더는 빌드하지 않습니다. 루트 `package.json` 스크립트만 사용합니다.

## 3. 정리 순서 (파괴적 삭제 없음)

- 1단계: 브리지와 통합 동기화 도입 (이번 작업)
- 2단계: 화면 코드를 통합 동기화로 교체 (다음 작업)
- 3단계: 1개월 안정 후 실험 폴더를 `archives/`로 이동 (개인 판단 후 실행)
